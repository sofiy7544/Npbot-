## 1. Что это за проект

**INTELLECT** — Telegram-бот + ИИ-ассистент для умного дома, который работает
**целиком на домашнем ПК пользователя** (Windows). Управляет:
- лампой **WLED** (свет, цвета, эффекты, сцены «сон/кино/дискотека…»),
- телевизором **Samsung** (пульт, приложения, громкость),
- самим ПК (статус, безопасные действия, перезагрузка/выключение — только с подтверждением),
- памятью, задачами, автоматизациями (по расписанию/событиям).

ИИ — облачный (OpenAI gpt-4o-mini / gpt-4o, Whisper для голоса), потому что
ПК слабый. Интерфейсы: Telegram (основной), веб-приложение для телефона (:8080),
панель INTELLECT 2.0 (:8090).

## 2. Пользователь и договорённости (ВАЖНО)

- Пользователь **не программист**. Пишет по-русски, коротко, бывает резко.
  Всё делает так: распаковал архив → двойной клик `START.bat` → пишет боту в Telegram.
- **Всё локально на ПК.** GitHub пользователю не нужен — не грузить его темой git.
- **Ключи кладём прямо в архив** (`.env` внутри), пользователь сам попросил:
  отдельный `.env` терялся, START.bat открывал пустой шаблон.
- **Перед отправкой архива — всё проверить** (тесты + проверка .bat в Wine, §6).
  Несколько архивов ушли непроверенными и ломались — пользователь это помнит.
- Отвечать по делу, без лишних вопросов; объяснять простыми словами.
- После каждой сборки отправлять **архив + отдельно этот HANDOFF.md**.

## 3. Как это работает на ПК — `START.bat`

1. Ищет Python (`py`/`python`), нет — скачивает и ставит 3.12 тихо.
2. Ставит библиотеки **один раз** (маркер `.deps_ok`), подробности → `logs\pip.log`.
3. Нет `.env` → создаёт из `.env.example`, открывает Блокнот, останавливается.
4. Первый запуск в папке → оптимизация ПК (`optimize_admin.bat` с UAC, маркер `.optimized`).
5. Автозапуск: ярлык `INTELLECT.lnk` в «Автозагрузке», **переписывается при каждом
   запуске** (путь передаётся в PowerShell через переменную окружения — так не ломаются
   буквы і/ґ в пути). Запасной вариант — Планировщик задач.
   ✔ Подтверждено на ПК пользователя 14.11 13:53 (`start.log`: «shortcut … OK»).
6. `find_lamp.py` ищет лампу.
7. Запускает `wled_bot.py` в цикле. Коды выхода бота:
   - **2** — проблема в `.env` (шаблон/неверный токен) → открыть Блокнот, остановиться;
   - **3** — уже работает другая копия (замок-порт 47831 или серия Telegram 409 Conflict
     у только что запущенной копии) → остановиться с объяснением;
   - иное (сеть упала и т.п.) → перезапуск через 5 с.

Окно никогда не закрывается молча (`:end` → pause).

## 6. Как разрабатывать и проверять

```bash
# окружение (один раз)
python3 -m venv /tmp/venv && /tmp/venv/bin/pip install -r requirements.txt
apt-get install -y wine gcc-mingw-w64-x86-64 unrar     # для проверки .bat и .rar
# тесты Python
/tmp/venv/bin/python tests/run_all.py                    # все должны пройти
# сборка архива (с .env пользователя внутри)
tools/build_release.sh /tmp/out  путь/к/.env_пользователя
# проверка .bat настоящим cmd.exe (Wine)
tools/test_bats.sh /tmp/out/INTELLECT-2.0
# и тесты внутри СОБРАННОЙ папки
(cd /tmp/out/INTELLECT-2.0 && /tmp/venv/bin/python tests/run_all.py)
```

Правила:
- **.bat**: только ASCII, CRLF (делает сборка), никаких `(` `)` в тексте echo внутри
  if-блоков (лучше вообще без блоков — через `goto`), `2>nul` перед `>>файл`.
- Новое поведение — с тестом; для важных исправлений — «контрольная мутация»:
  откатить исправление и убедиться, что тест падает.
- Из песочницы недоступны Telegram, OpenAI, ТВ, лампа: в тестах подмены
  (FakeProvider, фейковый слой запросов Telegram, имитация `shutdown.exe`).
- Wine — не Windows: его PowerShell — заглушка (создание ярлыка проверяется
  фейковым `powershell.exe`). Реальное поведение подтверждать по `start.log` пользователя.
- Секреты в тестах — только выдуманные (`1122334455:AAFakeToken…`, `sk-proj-FAKE…`).
  Сборка падает, если фрагмент настоящего секрета найден вне `.env`.

2. ✅ **ИИ и телевизор** — ВНЕДРЕНО. Уточнение причины: запросы к ИИ 13:56–13:58 были
   ДО настройки ТВ кнопками (13:59); ядро и кнопки и так делили `tvremote.config`.
   Сделано: единый конфиг (`tvremote.current()` перечитывает `tv.json` на ходу,
   `SAMSUNG_TV_IP` читается после `.env`), честное «не настроен → Найти телевизор»,
   новый инструмент `tv_status`. Тесты `tests/test_tv.py`.
3. ✅ **«Что идёт по телеку» не трогает питание** — ВНЕДРЕНО: у инструмента
   `tv_power` есть `intent` (явная просьба вкл/выкл/вруби/запусти…); без неё мозг
   вместо питания вызывает `tv_status`. Явную просьбу ищем и в 2 последних репликах
   пользователя («выключить телик?» → «да» работает). В 2.3.0 заменено на
   `tv_power_requested(text, history)`: глагол питания рядом со словом «телевизор», без
   причастий («включен?»), без «звук»; «да» — только после вопроса БОТА о питании ТВ.
4. ✅ **ТВ и «Разрешить?» / «ошибка сети»** — ВНЕДРЕНО в 2.2.1 (`tvremote.py`):
   причина — на каждое нажатие открывалась НОВАЯ сессия к ТВ и не закрывалась

   подтвердить по журналу пользователя (должна быть одна строка о токене, без ошибок на ТВ).
5. ✅ **Лампа при старте** — ВНЕДРЕНО в 2.2.1 (`find_lamp.py`, `wled_bot.py`): повторные

### Единый сайт и доступ извне — СДЕЛАНО в 2.3.0 (ждёт действий пользователя)
Что есть: `site/` (один интерфейс), единый API на :8090 (пароль + лимиты + CORS),
туннель Cloudflare (`TUNNEL=1`), `/panel` в Telegram присылает ссылку и пароль,
`panel_link.publish_api_url` пишет адрес туннеля в `api.json` репозитория сайта.
Как это работает для пользователя:
- Дома: `http://<ip ПК>:8090/` (ссылка в `/panel`).
- Откуда угодно: ссылка туннеля `https://….trycloudflare.com` — меняется при перезапуске
  ПК, бот присылает новую в Telegram (`/panel`).
- Постоянный адрес: сайт на **GitHub Pages в ОТДЕЛЬНОМ репозитории** (Pages этого репо
  занят магазином `stanleybrand.com.ua`, деплой из `docs/` по ручному workflow — НЕ трогать).
  Нужно от пользователя: создать пустой публичный репозиторий (например `intellect`),
  залить туда содержимое `site/`, включить Pages (Settings → Pages → Deploy from branch →
  main / root). Затем в `.env`: `PAGES_URL=https://<логин>.github.io/intellect/`,
  `GITHUB_PAGES_REPO=<логин>/intellect`, `GITHUB_TOKEN=<fine-grained token: Contents
  Read&Write только на этот репозиторий>` — и бот сам будет обновлять `api.json`.
  Без токена сайт на Pages попросит адрес API один раз после каждого перезапуска ПК.
- Пароль панели: `ACCESS_PASSWORD` в `.env` (в архиве пользователя задан случайный, 10
  символов; показывается в `/panel`). При слабом пароле туннель не поднимается.
Проверено: тесты (браузер Playwright против фейкового API и против настоящего сервера);
НЕ проверено вживую: cloudflared на Windows (скачивание ~20 МБ с GitHub при первом
запуске, скрытое окно), реальный GitHub Pages. Смотреть `logs\bot.log`: «🌐 Панель
доступна из интернета: …» и `logs\diag.txt` (строка «Туннель»).

Известные ограничения:
- Из песочницы нельзя проверить живой Telegram/OpenAI/ТВ/лампу.
- `git commit` в облачной сессии 14.11 блокировался проверкой прав (последний коммит
  `99d3a52`). **Источник истины — последний архив** (`BUILD_INFO.txt` это отмечает).

5. Сказать пользователю: распаковать **поверх** папки `INTELLECT-2.0` с заменой → `START.bat`.
